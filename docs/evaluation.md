# LogicScout evaluation protocol

This protocol was written before any results were collected. Results live in `docs/results.md`
(generated by `python -m logicscout.bench`) and in the raw per-seed JSON under `data/bench/`.
If a result disagrees with what we hoped, it is reported as-is.

## What is being claimed

LogicScout claims that, starting from a manual with no laws, it can (1) learn an executable theory
that predicts the world better than "nothing changes", (2) compile a playbook that meets an
objective on situations it never saw, without calling the model per step, and (3) notice a silent
change of the hidden laws and recover. Each claim is measured by an independent referee against
ground truth, never by the scout's own opinion.

## The referee

`logicscout.referee.evaluate(world_id, theory, playbook, objective_id, run_id, prompt_log, events)`
is the only privileged evaluator. It may import worlds directly; nothing the scout runs may import it
(enforced by the `scout_imports_clean` audit).

**Held-out cases.** Each world declares `referee_cases()`: seeds outside `manual.lab_seeds`
(by convention >= 10000) and variants other than `standard` (laws the scout never met in the lab).
Case ids are opaque (`case-0`, `case-1`, ...). The scout's sandbox port refuses non-lab seeds.

**Objective success.** For every case the referee builds a fresh world of that variant,
`reset(seed)`, and runs the controller up to the objective horizon:
`PlaybookRunner(playbook)`, or `PlannerPolicy(theory, manual, objective)` when the playbook origin is
`planner`. Success is `world.success(objective_id)`: the world's ground-truth check of its hidden state.
A controller crash counts as failure, with the error in the case note.

**Prediction accuracy.** On each case the referee collects 30 transitions under a random policy
seeded by the case seed (the scout cannot influence them) and scores `theory.accuracy` (fraction of
fields predicted correctly, excluding `t`). The baseline `persistence_accuracy` ("nothing changes")
is scored on the same transitions. A theory is only useful if it beats persistence.

**Baselines on the same cases.**
- `random`: uniform random admissible actions, seeded by the case seed.
- `idle`: only the wait/no-op action (or the playbook fallback if the world has none).
A success rate is only meaningful relative to these.

**Rule contradictions.** On standard-variant cases, every field mismatch is attributed to the
rules that produced the prediction. Rules implicated in mismatches are counted as contradicted by
held-out evidence (`false conclusions`).

## Leakage audit (each check is a boolean in the report; failures are shown, never dropped)

| check | passes when |
|---|---|
| `no_law_text_in_prompts` | the JSONL prompt log contains no `truth()` sentence of any variant, no numeric law value written next to its law name, and no law key that is not also a public manual name |
| `scout_imports_clean` | an AST scan of `logicscout/scout`, `logicscout/llm`, `logicscout/briefing` finds no import of `logicscout.worlds`/`logicscout.referee` and no access to `.laws`, `.truth`, `.referee_cases`, `.default_laws` |
| `referee_cases_unseen` | no seed used in a probe, control episode or run config is a referee seed, and standard-variant referee seeds lie outside `lab_seeds` |
| `events_digest_ok` | the logbook digest chain recomputes (`Logbook.verify`) |

When an input is missing (no prompt log, no events) the check is recorded as `false` with a note
saying it was **unverified**, so an absent audit can never pass silently.

**Digest.** The report digest is the sha256 of the canonical report. It proves the report was not
edited after the fact. It says nothing about whether the report is correct.

## Bench arms (matched budgets)

All arms on a world get the same probe budget (`manual.probe_budget`) and are scored by the same
referee on the same held-out cases. Every model call is a real Nemotron call through
`logicscout.llm.Nemotron`; the bench refuses to run without `NEBIUS_API_KEY`.

| arm | what changes |
|---|---|
| `full` | `run_mission` as shipped: briefing, active probing, theory, compiled playbook, drift monitor |
| `random_probe` | same budget, but probe actions are random; one theory-fitting model call at the end |
| `passive` | theory fitted from a random trajectory the agent did not choose (lab seed, same length) |
| `zero_shot` | the model picks every control action from the manual and observation history; no theory or playbook |
| `prompt_only` | the model may act/reset freely for the same budget, then must choose every control action itself (no compiled controller) |
| `no_briefing` | `full` with `use_briefing=False` |
| `no_transfer` | `full` with `use_transfer=False` (control for the transfer arm) |
| `no_adaptation` | `full` with a hidden change applied and the drift monitor disabled |
| `reasoning_control` | the full theory, but control by a model call per step instead of the compiled playbook |

Per-step model arms (`zero_shot`, `prompt_only`, `reasoning_control`) are run on the referee
cases through the referee's case runner with the model as the policy, so the success numbers are
directly comparable.

## Metrics

- objective success rate on referee cases (and `random`/`idle` baselines)
- probes to competence (probe steps used before the first playbook simulated to success)
- held-out prediction accuracy vs persistence
- recovery success and steps after a hidden change (arms that apply one)
- false conclusions: rules refuted later in the run + rules contradicted by referee transitions
- tool/API failure rate: failed model calls / all model calls
- tokens (prompt + completion) and model latency, from `ModelCall` events
- control actions and wall time

## Reporting rules

- `n` is tiny (a few seeds per arm). `docs/results.md` reports raw per-seed rows and plain means.
  No p-values, confidence intervals or significance language.
- An arm that crashes is reported as a crash with its error, not omitted.
- Leakage check failures appear in the table.
- Held-out cases and their seeds are never shown to the scout or written to any public event.
